# 保留原始截图的动态替换流程

独立模拟截图的画布尺寸、动态区域外的像素及受保护的游戏控件都与原始截图一致。用图像工具生成新动态，用 [replace_feed.py](../scripts/replace_feed.py) 将新内容贴回原始截图。最终 3:4 拼图再等比例缩放完整的模拟截图。

1. **确定目标区域。** 查看真实截图，定位粉色导航栏下面、白色帖子区域内的当前动态。区域包括料理图、头像、用户名、点赞数、评论和 Tags，结束于控制提示或下条动态之前。把 A 等叠在新动态区域内的游戏控件单独标成保护区。默认保留「B 关闭」、下方动态及截图底边。
2. **生成动态素材。** 以真实截图为编辑参考，用食物照片和可选头像作为内容参考。优先生成一张与目标动态区域宽高比相近的完整素材，上半段是料理插图，下半段是白底帖子信息，文字用足够的留白避免贴边。不要把整部手机、粉色导航栏、外部背景或关闭控件画进动态素材。图像工具若返回完整模拟截图，也可以选取其中新动态的矩形范围。
3. **合成。** `--base` 使用未经图像工具重绘的真实截图。`--feed-box` 是底图中的动态范围，四个值依次为左、上、右、下，右和下不包含在内。`--source-box` 仅用于从生成图中取出动态范围。`--keep-box` 可以重复指定，用于恢复游戏控件的原像素。以原图尺寸保存 PNG。
4. **复查。** 检查新内容是否准确，尤其是裁切边缘与文字。对独立模拟截图做像素比对，确认除动态区域外无差异，保护区也与原截图一致。将完整截图交给 `compose.py`，精确保真流程不使用底边裁切脚本。

例如本地 `班乔-白天-晴.JPG` 为 1280×720，动态区在 x=449 至 834、y=206 至 672。A 控件在动态区内，需单独保护。这些坐标是该参考图的示例，其他截图应先检查边界。

```bash
python3 scripts/replace_feed.py \
  --base "班乔-白天-晴.JPG" --patch generated-feed.png \
  --feed-box 449 206 835 673 --keep-box 790 515 814 541 \
  --output cooksta.png
```

如果用户另外要求移除关闭提示或调整背景，需要按这项新要求处理，并说明相应区域也会变化。若原始截图与所选时段或天气冲突，先取得匹配的截图。只在用户明确接受近似生成时，允许改变底图环境或从文字描述生成整张图。
