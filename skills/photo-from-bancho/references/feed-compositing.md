# 保留原始截图的动态替换流程

独立模拟截图只更换当前动态，并移除底部「B 关闭」及其半透明底框。画布尺寸、受保护的 A 控件和这两处之外的像素都与原截图一致。用图像工具生成新动态，用 [replace_feed.py](../scripts/replace_feed.py) 局部合成。最终 3:4 拼图等比例缩放完整的模拟截图。

1. **确定目标区域。** 查看真实截图，定位粉色导航栏下面、白色帖子区域内的当前动态。区域包括料理图、头像、用户名、点赞数、评论和 Tags，结束于关闭提示或下条动态之前。把叠在新动态区域内、需要保留的 A 等控件标成保护区。
2. **生成动态素材。** 以真实截图为编辑参考，用食物照片和可选头像作为内容参考。优先生成一张与目标动态区域宽高比相近的完整素材，上半段是料理插图，下半段是白底帖子信息，文字用足够的留白避免贴边。不要把整部手机、粉色导航栏、外部背景或关闭控件画进动态素材。图像工具若返回完整模拟截图，也可以选取其中新动态的矩形范围。
3. **合成。** `--base` 使用未经图像工具重绘的真实截图。`--feed-box` 是底图中的动态范围，四个值依次为左、上、右、下，右和下不包含在内。`--source-box` 仅用于从生成图中取出动态范围。`--keep-box` 可以重复指定，用于恢复游戏控件的原像素。以原图尺寸保存 PNG。
4. **复查。** 检查新动态和截图底部，确认 B 图标、关闭文字及底框均不可见。对独立模拟截图做像素比对，确认动态区和关闭提示区之外、以及保护区均与原图一致。将完整截图交给 `compose.py`。

当 `--base` 指向 Skill 的 `assets/scenes/` 内置截图时，脚本会自动使用对应的 `assets/close-patches/` 补片，清除范围为 `580 670 704 706`。例如内置 `班乔-白天-晴.JPG` 为 1280×720，动态区为 `449 206 835 673`。A 控件在动态区内，需单独保护。其他截图应先检查动态区和 A 控件边界。

```bash
python3 scripts/replace_feed.py \
  --base "assets/scenes/班乔-白天-晴.JPG" --patch generated-feed.png \
  --feed-box 449 206 835 673 --keep-box 790 515 814 541 \
  --output cooksta.png
```

自定义底图若有「B 关闭」，且没有被新动态完整覆盖，先用图像工具局部清除图标、文字及底框，从修正后的图裁出对应区域，再传入 `--close-patch clean.png --close-box LEFT TOP RIGHT BOTTOM`。补片必须与该区域等大，范围不得与保护区重叠。使用与内置底图像素一致的原图副本时，可显式传入对应的内置补片及坐标。底图没有关闭提示时可省略这两个参数。

若原始截图与所选时段或天气冲突，先取得匹配的截图。只在用户明确接受近似生成时，允许改变底图环境或从文字描述生成整张图；完整生成时同样不画关闭提示及底框。
